# Pricing Models

How the effort estimate becomes a price. Syncoria prices hybrid — T&M or fixed-fee depending on engagement model and phase. The governing rule: **you can't fix-price what isn't scoped yet.** Match the pricing approach to how certain the scope is.

## The certainty principle

Scope certainty rises through the methodology:
- **Pre-discovery** — scope is a guess. Only a ranged, caveated T&M or a phased estimate is honest.
- **Post-Phase-1 (PSS v1.0 signed)** — scope has shape but customizations aren't specified.
- **Post-Phase-4 (PSS v2.0 + CVBS library signed)** — scope is fully specified. This is the first point a confident fixed price for the build is defensible.

Syncoria's own methodology says no fixed price before the signed CVBS library. Pricing must respect this: the earlier the phase, the more the pricing leans T&M / ranged; the later, the more a fixed number is justified.

## By engagement model

### Full-Service
- **Early phases** — T&M against a ranged estimate, or a fixed price for the *discovery-through-specification* phases only (which are more predictable) with the build priced after Phase 4.
- **Build phase** — once CVBS library + PSS v2.0 are signed, a fixed-fee build becomes defensible. Many engagements split here: T&M (or fixed) for discovery→spec, fixed for build.
- **Common structure:** phased pricing — a fixed discovery/specification fee, then a fixed build fee set after scope is signed.

### Guided
- Syncoria isn't doing the delivery, so fixed-pricing the whole is rarely appropriate.
- **Common structure:** a fixed enablement/training package + T&M (or a capped retainer) for advisory, review, and escalation. Cap the advisory bank so the customer has cost certainty and Syncoria isn't open-ended.
- Reflect the variance: guided effort depends on customer pace/quality, so avoid committing to a fixed total.

### DIY / Self-Implementation with Support
- Bounded, defined scope (enablement + N checkpoints + support allowance) → **fixed package** is appropriate and usually expected.
- **Common structure:** a fixed price for onboarding + a defined number of checkpoint reviews + a bounded support-hours allowance. Overage beyond the allowance is T&M.
- Because scope is bounded, this is the most fix-priceable model despite being the cheapest.

## Presenting price in a proposal

- **Always a range** for anything not post-signed-scope. A single number pre-discovery is a false promise.
- **State the basis** — "T&M at [rate], estimated [low]–[high] hours" or "fixed fee of [X] for [defined scope]." Never a number with no basis.
- **Phase the commitment** where possible — let the customer commit to discovery/specification first, with the build priced once scope is signed. This is honest and de-risks both sides.
- **Separate the phases/workstreams** — discovery, specification, build, data, training, go-live as line items, so the customer sees where the money goes and can flex scope.
- **State what's excluded** — out-of-scope items, assumptions, and what triggers a change (ties to the CR process).
- **Customer effort is part of the cost** — especially guided/DIY. Make the customer's time commitment visible; it's real cost to them and affects the timeline.

## Rate application

This skill estimates *effort and structure*; apply Syncoria's current rate(s) to convert hours to price. If blended vs. role-based rates are used, apply per the current rate card. Keep the rate itself out of the skill's fixed content (rates change) — the skill produces the hours and the pricing structure; the user or the rate card supplies the rate.

## The honesty guardrail

Never present a fixed price for unscoped work to win a deal — it's the direct cause of the unbillable-overrun problem the methodology exists to solve. If a customer demands a fixed number pre-discovery, the right answer is a fixed price for discovery/specification plus a ranged estimate for the rest, with the build fixed once scope is signed. Protect Syncoria's margin by pricing to scope certainty, not to sales pressure.
